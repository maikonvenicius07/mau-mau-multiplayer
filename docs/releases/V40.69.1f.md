# MAU-MAU CANDEIAS — V40.69.1f

## Auditoria funcional desta correção

Base analisada: projeto completo enviado pelo usuário, identificado internamente como V40.69.1 com a correção V40.69.1c do botão **⇄ Trocar lados**.

### Problemas concretos corrigidos

1. **Arraste do botão Trocar lados dependia do próprio botão**
   - O `pointermove`/`pointerup` ficava vinculado ao controle e dependia de `setPointerCapture()`.
   - Em Safari/WebView e em alguns gestos móveis isso pode perder o movimento quando o dedo sai da área original.
   - Agora o movimento e o término do gesto são acompanhados pela `window`.

2. **Faltava fallback explícito para Touch Events**
   - Foi adicionado `touchstart`, `touchmove`, `touchend` e `touchcancel` como fallback para navegadores/WebViews em que Pointer Events não seja confiável.
   - Também existe fallback de mouse quando `PointerEvent` não estiver disponível.

3. **O botão continuava dentro do `felt` no HTML**
   - Mesmo com `position: fixed`, isso criava dependência desnecessária da estrutura visual da mesa.
   - O botão foi movido para fora do `felt` e agora é um controle global do `#game`, como o microfone.

4. **Cache podia manter JavaScript antigo depois do deploy**
   - `app.js` e `styles.css` usavam a mesma versão `?v=40.69.1`, enquanto o servidor permitia cache fresco por até 1 hora.
   - Isso podia fazer o celular continuar executando a versão anterior mesmo depois de um deploy correto.
   - Agora a página usa `?v=40.69.1f` e JS/CSS são enviados com `Cache-Control: no-cache, must-revalidate`.

5. **A alça de arraste ficava escondida em telas muito pequenas**
   - Em telas de até 480 px, a alça `⠿` agora permanece visível e o rótulo textual é ocultado para manter o controle compacto.

## Configuração externa ainda necessária para login universal em produção

O código está preparado, mas os provedores só aparecem quando o Render possui as variáveis correspondentes:

- E-mail: `RESEND_API_KEY` e `EMAIL_FROM`.
- Apple: `APPLE_CLIENT_ID`, `APPLE_REDIRECT_URI`, `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY`.

Sem essas credenciais, Google continua funcionando, mas Apple/e-mail permanecem ocultos por segurança.
