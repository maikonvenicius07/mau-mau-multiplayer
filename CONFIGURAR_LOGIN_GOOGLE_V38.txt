CONFIGURAÇÃO DO LOGIN GOOGLE — MAU-MAU V38

Esta versão NÃO possui modo visitante. Sem GOOGLE_CLIENT_ID configurado, o jogo mostra a tela de login, mas bloqueia a entrada até a configuração ser concluída.

1) GOOGLE CLOUD
- Acesse o Google Cloud Console / Google Auth Platform.
- Crie ou selecione um projeto.
- Configure a tela de consentimento/Branding e o público do aplicativo.
- Crie um Cliente OAuth do tipo "Aplicativo da Web".
- Em "Origens JavaScript autorizadas", cadastre a URL HTTPS do jogo no Render.
  Exemplo: https://SEU-SERVICO.onrender.com
- Para testes locais, adicione também: http://localhost:3000
- Copie o Client ID terminado em .apps.googleusercontent.com.

2) RENDER — ENVIRONMENT
No serviço web do Mau-Mau, adicione:

GOOGLE_CLIENT_ID = SEU_CLIENT_ID.apps.googleusercontent.com
AUTH_SESSION_SECRET = UMA_CHAVE_LONGA_E_ALEATORIA

Sugestão para gerar a chave em um terminal:
openssl rand -hex 32

Não coloque essa chave no GitHub. Mantenha AUTH_SESSION_SECRET constante; se ela for trocada, as sessões já abertas serão encerradas.

3) DEPLOY
- Salve as variáveis no Render.
- Faça Manual Deploy > Deploy latest commit.
- Depois de ficar Live, abra o site em uma janela anônima e confirme que somente o botão "Entrar com Google" aparece antes do jogo.

4) TESTE RÁPIDO
- Entre com Google.
- Confirme nome/foto da conta no topo da tela inicial.
- Crie uma sala e jogue normalmente.
- Abra em outro dispositivo com a mesma Conta Google: a identidade do jogador será a mesma.
- Use "Sair da conta" na tela inicial e confirme que não é possível criar/entrar em sala sem novo login.

OBSERVAÇÃO SOBRE RANKING
A estrutura e o banco PostgreSQL não foram alterados. A V38 muda somente a forma de produzir o playerKey: agora ele é estável por Conta Google. Registros antigos feitos com o playerKey local permanecem no banco, mas não são automaticamente fundidos com a nova identidade Google.
